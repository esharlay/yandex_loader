# Yandex Loader

Нативный двухпанельный файловый менеджер для macOS 14+ на Apple Silicon. Интерфейс на русском, AppKit. Приложение работает без App Sandbox. Для обновлений используется Sparkle 2.10.1.

## Запуск

Скачайте ZIP из [последнего релиза](https://github.com/esharlay/yandex_loader/releases/latest), распакуйте и перенесите `Yandex Loader.app` в «Программы». Сборка подписана ad-hoc, без платного сертификата Developer ID и нотариального заверения Apple. Если macOS попросит подтвердить запуск скачанного приложения, используйте штатную команду «Открыть» в Finder или разрешение в «Системные настройки → Конфиденциальность и безопасность».

## Обновления

Начиная с версии 1.4.0 приложение проверяет обновления примерно раз в сутки и предлагает установить новую версию. Для ручной проверки выберите «Yandex Loader → Проверить обновления…». Если идёт передача файлов, перезапуск для установки ждёт её завершения. Первую версию с обновлениями нужно установить вручную на каждом Mac.

Архивы находятся в GitHub Releases, подписанная лента — `appcast.xml` в этом репозитории. Приложение проверяет подпись Ed25519 ленты и архива до распаковки. Закрытый ключ хранится в Связке ключей владельца и в репозиторий не попадает. Авторизация Яндекс Диска настраивается отдельно на каждом Mac.

Порядок выпуска следующей версии описан в [PUBLISHING.md](PUBLISHING.md).

Для папок «Рабочий стол», «Документы», «Загрузки» и подключённых дисков macOS может запросить доступ. При отказе приложение показывает ошибку и кнопку перехода в настройки конфиденциальности.

Левая панель при первом запуске открывает `~/work`, если папка существует, иначе домашнюю папку. Правая — Яндекс Диск. При подключении аккаунта она открывает `disk:/models`, если папка есть. Затем пути панелей сохраняются между запусками.

## Первое подключение Яндекс Диска

1. На [oauth.yandex.ru](https://oauth.yandex.ru/) создайте своё приложение типа «Для доступа к API или отладки».
2. Включите права `cloud_api:disk.read` и `cloud_api:disk.write`.
3. Скопируйте Client ID. В Yandex Loader откройте «Файл → Подключить Яндекс Диск…» или кнопку настроек, вставьте Client ID и нажмите «Войти через Яндекс».
4. Завершите вход в открывшемся окне. Приложение извлекает токен из адреса ответа Яндекса. Если при настройке приложения требуется Redirect URI, укажите `yandexloader://oauth`. Приложение также умеет перехватить токен со страницы подтверждения Яндекса, если используется стандартный адрес возврата.
5. Если автоматический возврат не сработал, вставьте готовый OAuth-токен или полный адрес страницы с `#access_token=…` в поле «Готовый токен или адрес после входа».

Токен проверяется перед сохранением. Client ID хранится в настройках; токен — только в Связке ключей: служба `com.blueeggs.yandexloader`, запись `accessToken`. Секрет клиента не нужен. Не присылайте токен в чат.

Описание сервиса: [официальный REST API Яндекс Диска](https://yandex.ru/dev/disk/rest/).

## Работа с файлами

Один щелчок выделяет, двойной открывает. Shift и Command позволяют выделить несколько объектов. Щелчок по боковой панели открывает место в активной файловой панели. Её отмечает синяя полоска сверху. Потяните за тонкий разделитель между списками, чтобы изменить ширину панелей.

Две маленькие кнопки без подписей находятся прямо поверх тонкого разделителя: сверху копирование, снизу перенос. При выборе одного объекта они стоят напротив его строки; при выборе нескольких — посередине между верхней и нижней выбранной строкой. Положение обновляется при прокрутке. Если выделение ушло за край списка, кнопки остаются у ближайшего видимого края. Без выделения кнопки серые и стоят в середине списка. Названия операций доступны во всплывающих подсказках. Стрелка переноса направлена от панели-источника к соседней панели. Источник — панель с выделением; если выделение есть в обеих, используется активная. Направление видно на кнопках. Перетаскивание между панелями копирует; Option во время отпускания перемещает.

| Команда | Сочетание |
| --- | --- |
| Другая панель | Tab |
| Открыть | ⌘O или ⌘↓ |
| Переименовать | Enter |
| Быстрый просмотр / закрыть просмотр | Пробел |
| Следующий / предыдущий файл в просмотре | ↑ / ↓ (также ← / →) |
| Вверх | ⌘↑ |
| Назад / вперёд | ⌘[ / ⌘] |
| Копировать / вырезать / вставить | ⌘C / ⌘X / ⌘V |
| Переместить из буфера | ⌥⌘V |
| Новая папка | ⌘⇧N |
| В Корзину | ⌘⌫ |
| Обновить обе панели | ⌘R |

Буфер файлов внутренний. В текстовых полях работают обычные команды редактирования macOS. Копирование пути использует системный буфер. Набор букв в таблице переходит к имени файла.

Сортировка по группам дат выбирается справа от фильтра. Заголовки колонок переключают сортировку по имени, дате или размеру; повторное нажатие меняет направление. Фильтр действует только на текущую папку. Локальные изменения отслеживаются автоматически, содержимое Диска обновляется после операций и по ⌘R.

В избранное добавляется текущая локальная папка. Собственные пункты можно убрать через контекстное меню; системные места остаются.

## Передачи и сохранность файлов

Поддерживаются все четыре направления: локально ↔ локально, локально ↔ Диск и Диск ↔ Диск. Облачное копирование и перемещение выполняются сервером. Папки обходятся рекурсивно, `.DS_Store` при обходе пропускается. Самокопирование папки, в том числе через локальную символическую ссылку в назначении, блокируется.

Для передачи между компьютером и Диском и для локального копирования результат сначала собирается в отдельном временном объекте, затем получает конечное имя. Исходный объект при переносе отправляется в Корзину только после успешной передачи всей его вложенной структуры. Незавершённые временные объекты убираются при обработке ошибки или отмены. Локальные символические ссылки копируются как ссылки; при загрузке ссылки на Диск выводится объяснение, что нужно выбрать сам файл.

Совпадение имени вызывает выбор: заменить, пропустить, оставить оба или отменить. «Применить ко всем» относится к текущей операции. Замена отправляет предыдущую версию в соответствующую Корзину. «Оставить оба» добавляет номер перед расширением.

Внизу показаны имя текущего файла и общий прогресс по объёму данных. Нажмите на правую часть строки состояния или выберите «Вид → Передачи», чтобы открыть отдельное окно. В нём показаны все файлы очереди, включая вложенные файлы выбранных папок: имя, размер, переданный объём, процент и состояние. Загрузка идёт последовательно; у ожидающих файлов состояние «В очереди». Крестик отменяет один ожидающий или передаваемый файл, остальные продолжают передачу. «Отменить все» останавливает всю операцию. «Свернуть» и закрытие окна списка не отменяют передачу. После завершения список доступен до начала следующей операции.

Прогресс отправки и скачивания обновляется во время передачи файла по сетевым событиям. Общий процент учитывает размеры файлов: большой файл имеет больший вес, чем маленький. Отменённые и пропущенные файлы исключаются из оставшегося объёма. Состояние «Завершение» означает, что данные уже переданы, а приложение публикует готовый результат; в этот момент индивидуальная отмена уже недоступна. Для серверных операций Диск → Диск точный процент недоступен: вместо него показано состояние «Выполняется на Диске».

Если отменён один файл внутри переносимой папки, остальные файлы копируются в папку назначения, а исходная папка целиком сохраняется. Такая операция отмечается как частичная. Если отменён отдельный файл верхнего уровня, его исходник остаётся на месте, незавершённая копия убирается. Если сервер Диска уже принял операцию копирования или перемещения, остановка ожидания не отменяет саму серверную операцию: у REST API нет команды её отката. Выполненные до отмены элементы сохраняются.

## Просмотр моделей

STL, PLY, GLB и GLTF имеют отдельные загрузчики; OBJ, USD, USDA, USDC, USDZ, DAE, ABC и SCN загружаются через SceneKit / Model I/O macOS. Окно позволяет вращать и масштабировать модель, показывает количество треугольников и габариты в единицах файла. По умолчанию верх направлен по оси Y: STL и PLY сохраняют ориентацию из файла. Для файлов, экспортированных с осью Z вверх, включите «Для STL и PLY ось Z смотрит вверх» в настройках. GLB/GLTF и остальные форматы сохраняют оси из файла. Камера начинает с ракурса в три четверти немного сверху и нацелена на центр модели после всех поворотов.


Открытое превью следует за выделением в активной панели: выберите другой файл мышью или нажмите ↑/↓ в списке, и превью загрузит его, сохраняя фокус в списке. Стрелки в самом окне просмотра и его кнопки «назад/вперёд» тоже переходят к соседнему файлу и синхронно меняют выделение. Используется текущий порядок сортировки и фильтра, папки пропускаются. На границе списка переход останавливается. Быстрые последовательные нажатия отменяют загрузку устаревшего выбранного файла.

Освещение подчёркивает рельеф: направленный свет сверху сбоку, слабый заполняющий свет и более глубокие тени в углублениях. Источники света следуют за камерой при вращении.

Обычные GLB/GLTF 2.0 поддерживают иерархию узлов, трансформации, сетки, материалы и основные текстуры. Просмотр статический: проигрывание анимаций, деформация скелетом, Draco/meshopt и разреженные accessor не реализованы. Для моделей с таким экспортом используйте обычный статический GLB без сжатия. Возможность чтения вариантов USD/ABC/SCN зависит от импортёров macOS; ошибка формата выводится в окне просмотра.

Другие файлы открываются в системном Быстром просмотре. Для облачных файлов используется кэш `~/Library/Caches/com.blueeggs.yandexloader/Preview`. Файлы кэша, не использовавшиеся больше недели, очищаются при запуске. Для GLTF и OBJ загружаются также связанные буферы, материалы и текстуры внутри той же папки; сетевые ссылки и выход через `..` в удалённых зависимостях запрещены.

## Сборка без Xcode

Нужны Command Line Tools со Swift 5.9+; проверено на Swift 6.1.2, архитектура arm64. При первой сборке Swift Package Manager скачивает официальный двоичный Sparkle 2.10.1 с проверкой закреплённой SHA-256 суммы. Framework включается внутрь приложения с исходной подписью Sparkle; приложение получает локальную ad-hoc подпись.

```sh
./build.sh
```

На выходе — `Yandex Loader.app` в родительской папке проекта. Другую папку можно передать первым аргументом. Идентификатор приложения: `com.blueeggs.yandexloader`, URL-схема: `yandexloader`. Команда также ставит и проверяет ad-hoc подпись.

```sh
./test.sh
```

Проверки запускаются отдельной программой, без XCTest, который не поставляется в обычном комплекте Command Line Tools. Они используют только собственные временные папки и имитацию HTTP-ответов. Реальный аккаунт и файлы пользователя не изменяются.

## Проверено

Автоматически: пути и защита от копирования в себя, группы дат, токены из адреса, страницы по 200 объектов, заголовок OAuth, ответы 401/404/202, рекурсивное копирование, скрытые файлы, исключение `.DS_Store`, конфликты и «Применить ко всем», сохранение исходников при ошибке и отмене, отмена отдельного активного и ожидающего файла с продолжением очереди, частичная передача папки без удаления исходников, общий прогресс с учётом размера файлов, реальный сетевой прогресс отправки и скачивания на локальном тестовом сервере, серверное перемещение, STL/PLY/GLTF/GLB, выделение, фильтр и привязка контекстной команды к своей панели.

В живом окне проверены одиночное выделение и включение кнопок передачи, а также список очереди и отмена отдельной строки в отдельном демонстрационном окне. Во время проверки пользователь подключил аккаунт; загрузка реального списка Яндекс Диска подтверждена. Тестовая передача в пользовательский аккаунт не выполнялась.
